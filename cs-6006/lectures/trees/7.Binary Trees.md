# Binary Trees

## Goal

### Sequence Interface

We want to achieve good performance i.e. log(n) with all operations. This is a
trade off in case of `insert_first/last` or `delete_first/last` in comparison
with other Data structures we have worked with so far, but we get `log(n)` in
`delete_at` operations.

### Set Interface

Hash tables are very good with finding specific keys and items related to them,
but not with finding `closest_match` or `prev/next` operations. Sorted arrays
give us that due to base case of binary search, but sorted arrays are bad with
dynamic operations.

#### **Trees do all the efficiently**

## Terminology

- A **root** of a tree has no parent.
- A **leaf** of a tree has no children.
- **Depth** of a node X is number of edges from the root R to X.
- **Height** of a node X is the max number of edges from it to the leaf of the tree.
- **In order traversal** is Left Node -> Parent Node -> Right Node.

> [!NOTE]
> Currently traversal orders do not have any meaning, they are specific to the
> data structure itself, we can use this order to implement Sequence/Set interfaces.
> In simple implementation, to implement Sequence interface, match the array order
> with the tree order. For Set interface, sort the keys/values in the set and then
> match that order with tree order.

## Operations

- **First()**: The left-most, non-none leaf of the sub-tree.
- **Last()**: The right-most, non-none left of the sub-tree.
- **Successor()**: Next after node in trees **In order** traversal order.
  - If Right child available:
    - The **First** node in the right subtree if available.
  - Else if it is left child of the parent
    - Then parent is the successor.
  - Else
    - Go up till you find a node that is a left child of the parent,
      return the parent of that node.
- **Insert_after()** _left is symmetric_ :
  - If no right child:
    - put the new node there.
  - else:
    - left child of the successor of node.
- **Delete**:
  - If node is leaf:
    - Delete it.
  - Else if Node.left:
    - replace node with it's predecessor till it becomes leaf and then delete it.
  - Else Node.right:
    - replace node with it's successor till it becomes leaf and then delete it.

## Implementing Set Interface (Set Binary Tree)

As mentioned earlier, the tree order represents the key order. So that binary
search can be applied on the tree to find the items.

To implement this, keep this order in mind while building the tree, put each
item in the right in-order place.

## Implementing Sequence Interface (Sequence Binary Tree)

- Traversal order = Sequence order
- **subtree_at(node, i)**:

  - nl = size(node.left)
  - if i < nl:
    - subtree_at(node.left, i)
  - if i = nl:
    - return node
  - if i > nl:
    - subtree(node.right, i-nl-1)

- **subtree_at** can be used for the `get_at()`, `insert_at()` and `set_at()` operations.

### Subtree Augmentation

We store some information in each node, so that the calculation becomes smaller
and easier. Specifically, a **subtree** property, that is dependent and can be
calculated using a node's children's `subtree` property. We can store the
`size` property like this. Others can be `sum`, `product`, `min`, `max` etc.

> [!IMPORTANT]
> Don't store global properties in the nodes, since they depend upon the entire
> tree and result in linear time operations. Properties like `index`, `depth` etc.
> So, rule of thumb, only store properties that depend upon a Node's children.

## Height Balance

We want to make sure that a binary tree maintains O(logn) height under dynamic
operations. Therefore we need height balanced trees.

- Red Black, Splay Trees, 2-3 Trees, ...
- AVL Tree

### Rotations

Change the height of the tree without changing its traversal order, Therefore
not changing the underlying Set or Sequence implementation scheme.
